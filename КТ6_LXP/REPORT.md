# КТ № 6. Проверка качества описания API

## 1. Чек-лист проверок

| Проверяемая фраза | Начальные данные | Ожидание по черновику | Запрос для проверки состояния |
|---|---|---|---|
| POST: повторное создание задачи с тем же name отклоняется | Нет задач с выбранным именем | Первый POST — 201, повторный — 409 | GET /todoitems |
| PUT: пропущенное name сохраняет прежнее значение | Две задачи с одинаковым name и isComplete=false | PATCH и PUT — 204; name сохраняется, isComplete становится true | GET /todoitems/{id} после каждого обновления |
| DELETE: повторный запрос возвращает 204 | Существующая задача с известным id | Первый и повторный DELETE — 204 | GET /todoitems/{id} после каждого удаления |
| GET /todoitems/complete возвращает только выполненные задачи | Задачи с известными значениями isComplete | 200, все элементы имеют isComplete=true | GET /todoitems/complete |

## 2. Журнал запросов

Исходное состояние: GET /todoitems — 200 OK, пустой массив [].

| Запрос | Статус | Результат |
|---|---|---|
| POST /todoitems, name=KT6_DUPLICATE_PROBE_2511, isComplete=false | 201 Created | Создана задача id=1 |
| Повторный POST с тем же телом | 201 Created | Создана задача id=2 |
| GET /todoitems | 200 OK | Обе задачи существуют, name одинаковый |
| PATCH /todoitems/1, {"isComplete":true} | 204 No Content | GET /todoitems/1: name сохранился, isComplete=true |
| PUT /todoitems/2, {"isComplete":true} | 204 No Content | GET /todoitems/2: name=null, isComplete=true |
| GET /todoitems/complete | 200 OK | Возвращены задачи id=1 и id=2, обе с isComplete=true |
| DELETE /todoitems/2 — первый запрос | 204 No Content | GET /todoitems/2: 404 Not Found |
| DELETE /todoitems/2 — повторный запрос | 404 Not Found | GET /todoitems/2: 404 Not Found |

## 3. Замечания по документации

| Цитата и критерий | Ожидание по черновику | Факт и проверка состояния | Точная правка или вопрос |
|---|---|---|---|
| «Если задача с таким name уже есть, повторное создание отклоняется». Критерий: проверяемость, непротиворечивость. | Повторный POST должен вернуть 409 Conflict. | Оба POST вернули 201 Created. Созданы две задачи с одинаковым name и разными id (1 и 2). GET подтвердил наличие обеих записей. | Указать, что повторный POST с тем же name создаёт отдельную задачу с новым id и возвращает 201 Created. |
| «Для смены только статуса достаточно передать isComplete; пропущенное поле name сохранит прежнее значение». Критерий: однозначность, проверяемость. | PUT с одним isComplete должен сохранить name. | PUT вернул 204, но GET /todoitems/2 показал name=null и isComplete=true. Для сравнения PATCH с тем же телом сохранил прежнее name. | Указать: при PUT пропущенное name становится null. Для изменения только isComplete без потери name следует использовать PATCH. |
| «Повторный DELETE с тем же id также возвращает 204, потому что удаление идемпотентно». Критерий: точность, проверяемость. | Первый и повторный DELETE должны вернуть 204. | Первый DELETE вернул 204, повторный — 404. После обоих запросов GET возвращал 404: задача отсутствовала. Эффект удаления идемпотентен, но статус повторного запроса отличается. | Указать: первый DELETE существующей задачи возвращает 204; повторный DELETE отсутствующей задачи возвращает 404. |

## 4. Подтверждённое утверждение

Утверждение о GET /todoitems/complete подтверждено: запрос вернул 200 OK и массив, содержащий только задачи с isComplete=true. Поэтому оно не включено в замечания.

## 5. Сортировка

В предоставленном файле api-description-file.md предложение редактора о сортировке отсутствует. Поэтому проверить его точную формулировку невозможно. В любом случае одного наблюдаемого списка недостаточно, чтобы объявить порядок элементов гарантией API.

## 6. Самое опасное замечание

Самое опасное замечание — поведение PUT: успешный ответ 204 сопровождается потерей прежнего значения name, что может привести к незаметной потере пользовательских данных.
